# HANDOFF — Study Planner 프로젝트

## 1. 프로젝트 목적

**이 프로젝트가 무엇인지**
- 단일 HTML 파일(`index.html`) 기반의 학습 플래너 웹앱
- Firebase Realtime Database(compat SDK)로 데이터 동기화 (익명 로그인)
- 계산기(할당량 계산), 캘린더(일정 관리 + 회독), 일정표(timetable) 세 가지 기능으로 구성
- GitHub Pages로 배포 (레포 루트 `index.html`이 실제 서비스 URL, `공부앱/index.html`이 원본 — 두 파일은 항상 동일하게 유지해야 함)

**현재 목표**
- 지난 세션의 전체 코드 리뷰(버그/성능/코드 정리/신규 기능)를 기준으로 계획한 개선 작업을 모두 구현 완료한 상태
- 이번 세션에서 일정표 합계 기능(데스크탑 주간뷰 + 모바일 일단위뷰)을 복원/추가 완료
- 다음 목표는 사용자의 실사용 피드백(특히 모바일 환경)을 받아 다듬는 것 — 현재 명시적으로 남은 신규 요청 없음

## 2. 현재까지 완료한 작업

### 최신 세션 (일정표 합계 복원)
- **일정표 데스크탑 주간뷰 합계 열/행 복원** — `renderTimetable()`에서 업무별 주간 합계(`td.tt-total`, 각 행 끝) + 요일별 합계 행(`tr.tt-total-row`, 표 맨 아래) 추가. 기존 CSS(`.tt-total`, `.tt-total-row`)는 있었지만 렌더링 로직이 빠져 죽어있던 것을 복구
- **일정표 모바일 일단위뷰 합계 행 추가** — 데스크탑에는 있었지만 모바일 목록형 뷰에는 없던 "합계" 항목을 하루치 업무 값 합산으로 새로 추가 (기존 기능 복원이 아닌 신규 보완)
- 커밋: `bb93ee0`(데스크탑 합계 복원), `b453a22`(모바일 합계 추가) — 둘 다 `origin/main`에 push 완료

### 최근 세션(코드 리뷰 기반 개선)에서 구현된 기능

**버그 수정**
- `undoMarkStatus`가 커스텀 `nextDays`를 무시하고 항상 기본 간격(1/3/7일)으로 다음 회독 항목을 찾던 버그 수정 → 완료 취소 시 정확한 날짜의 항목이 삭제됨
- 계산기 화면에서 브라우저 리사이즈(데스크탑↔모바일 폭 전환) 시 사이드바/결과 영역이 모두 사라지던 버그 수정 → `resize` 리스너 추가(`initCalcMobileState`, 150ms 디바운스)

**성능 개선**
- `autoSaveDraft`를 200ms 디바운스로 분리(`autoSaveDraftNow`) — 매 keystroke마다 전체 카드 순회 + localStorage 쓰기가 발생하던 문제 완화

**코드 정리**
- `.task-name-modal`의 죽은 CSS 선언(`font-size:4px`) 제거
- Firebase 계산기 동기화의 저장목록/드래프트 LWW 비교 로직을 `applyIfNewer()` 공통 헬퍼로 통일 (폴더트리/폴더순서는 특수 분기가 많아 유지)
- localStorage 읽기/쓰기 실패 시 조용히 무시하던 catch에 `showToast` + `console.error` 추가
- `saveFirebaseConfig`의 `alert()` → `showToast`, `removeCalcTask`의 `confirm()` → `openConfirm` 커스텀 모달로 통일 (토스트가 모달 위에도 보이도록 `#toast` z-index 999→2100 상향)
- 저장 항목 메타(`saved-item-meta`)의 `qty`/요일별 목표값에도 `esc()` 일관 적용

**신규 기능**
- **캘린더 "🧹 정리" 버튼** — 6개월 이전 오래된 일정을 사용자 확인 후 일괄 삭제(`confirmArchiveOldCalTasks`)
- **휴일 제외 UI** — task-card에 "휴일 제외 날짜" 입력 필드 추가, `calculate()`가 실제로 반영(이전엔 `holidays=[]` 하드코딩으로 죽어있던 기능). 드래프트 저장에도 `holidays` 필드 영속화
- **계산 결과 "📋 결과 복사" 버튼** — 클립보드 복사(Clipboard API + execCommand 폴백)
- **"📈 통계" 탭 신규 추가** — 전체/완료/완료율/연속 완료일(스트릭), 회독 단계별 완료 현황, 최근 30일 막대 그래프(`renderStats()`)

**검증 완료**: 브라우저 프리뷰에서 JS 문법 오류 없음, undo 버그 재현 테스트로 수정 검증, 리사이즈 이벤트 강제 발생시켜 레이아웃 복구 확인, 홀리데이 입력→계산→저장 전체 흐름 확인, 통계 뷰 집계 로직 검증, 새로고침 후 드래프트(휴일 필드 포함) 정상 복원 확인

**의도적으로 보류한 항목** (우선순위 "하"로 분류)
- Firebase push를 `.set()` 전체 전송 대신 부분 `.update()`로 바꾸는 것 — 동기화 프로토콜 자체를 건드리는 위험도가 높아 보류. 대신 "정리" 기능으로 데이터 크기 자체를 억제
- `prompt()` 네이티브 다이얼로그(새 폴더 이름 입력 등) — 텍스트 입력용 커스텀 모달이 없어 그대로 둠, 신규 컴포넌트 제작은 과도한 리팩토링으로 판단
- Firebase API Key 저장 방식(localStorage 평문) — 설계상 정상 범위로 판단해 미조치

### 이전 세션들에서 완료된 주요 작업
- **시간표 → 일정표** 이름 변경 전체 적용
- **일정표 달성 체크 로직 개선**: `isCalTaskLinkedDone()` — `linkedCalc === calcTaskName` && `progressStep` 합계 ≥ 일일 할당량
- **일정표 타임존 버그 수정**: `toISOString()` 대신 `calDateKey()`로 로컬 날짜 사용
- **모바일 캘린더 셀**: 일정 미리보기 제거 → 개수 뱃지만 표시 (기본/미완료 빨간색, 부분 노란색, 완료 초록색)
- **캘린더 날짜 모달 → 모바일 바텀시트** 리디자인, 닫기 버튼 크기 고정
- **폴더 플리커 버그 수정**: 클릭 시 DOM 직접 토글, 전체 재렌더 방지
- **결과 블록 접기 동기화** 및 접기/펴기 버튼 분리(입력 패널/결과 패널 독립)
- **삭제 확인 다이얼로그**, **모든 업무 저장** 버튼 추가
- **캘린더 모달 컴팩트화**: 순서 버튼(9px)/이름 폰트(4px+줄바꿈)/진척도 입력칸(스피너 제거+가운데정렬)/액션 버튼(9px 3열) 등 모바일 전용 축소, 데스크탑은 원본 유지 (`@media (max-width: 640px)` 안에만 적용)

## 3. 현재 프로젝트 상태

**정상 작동하는 부분**
- 계산기 전체 기능 (할당량 계산, 휴일 제외, 저장/불러오기, 폴더 관리, 결과 복사)
- 캘린더 전체 기능 (일정 추가/수정/삭제, 이동/복사, 연동 추가, undo, 오래된 일정 정리)
- 일정표 달성 체크 (linkedCalc + progressStep 기반), 데스크탑 주간 합계 열/행 + 모바일 일단위 합계
- 통계 탭 (완료율, 스트릭, 30일 그래프)
- 모바일 바텀시트 모달, 계산기 리사이즈 대응
- Firebase 데이터 동기화 (익명 인증, LWW)

**확인이 필요한 부분**
- 모바일에서 4px~9px대 축소 폰트(일정 이름, 버튼)의 실기기 가독성 — 사용자 확인 대기
- 모바일 완료/미완료/이동/복사/삭제 3열 버튼 레이아웃 실제 기기 확인
- 통계 탭 스트릭 계산 로직의 엣지 케이스(일정이 아예 없는 기간이 긴 경우) — 로직상 스킵 처리되나 실사용 데이터로 재확인 권장

**현재 발생 중인 오류/문제**
- 없음. 마지막 커밋(`b453a22`) 기준 정상, `origin/main`에 push 완료됨

## 4. 변경한 파일 목록

| 파일 | 변경 내용 |
|------|-----------|
| `공부앱/index.html` | 원본 앱 파일 — 버그 수정/성능 개선/코드 정리/신규 기능(휴일 제외, 결과 복사, 통계 탭) 전체 반영 |

- `관리앱/` — 완전히 별개 프로젝트(phone-lock-android/desktop). 항상 미터치

## 5. 아직 남은 작업

현재 사용자로부터 명시적으로 남은 요청 없음. 일정표 합계 기능(데스크탑+모바일) 요청은 이번 세션에서 완료.

**잠재적 개선 후보 (우선순위 순)**
1. 모바일 실기기에서 축소 폰트/버튼 레이아웃 확인 후 필요시 크기 재조정
2. 모바일 바텀시트 drag-to-dismiss 제스처 (아직 미구현)
3. (보류 중) `prompt()` 대체용 텍스트 입력 커스텀 모달 — 폴더명 입력 등에서 필요해지면 검토
4. (보류 중) Firebase push를 `.update()` 기반 부분 전송으로 전환 — 데이터량이 "정리" 기능으로도 감당 안 될 만큼 커지면 재검토

## 6. 다음 세션에서 바로 시작할 작업

**가장 먼저 할 일**
- 사용자의 모바일 실사용 피드백 확인 후 그에 맞게 수정 (특별한 지시 없으면 대기) — 일정표 합계 기능도 실기기에서 레이아웃/가독성 확인 권장

**주의할 점**
- **절대 `git push` 먼저 하지 말 것** — 사용자가 "push해"/"올려" 등으로 명시할 때만 push
- push 전에는 항상 **레포 루트 `index.html`이 `공부앱/index.html`과 동기화되어 있는지 확인** — 루트 파일이 없거나 오래된 상태로 push하면 `.github/workflows/deploy.yml`이 그대로 배포해 기존 GitHub Pages URL이 깨질 수 있음
- 크기/스타일 변경 시 데스크탑은 `@media` 밖(전역), 모바일 전용은 `@media (max-width: 640px)` 안에 작성
- `step-input-modal`은 JS에서 `className`으로 클래스 부여 — 인라인 스타일로 `width/font-size` 지정하면 미디어쿼리 override가 안 됨
- Firebase push(git)는 항상 `origin master:main` (로컬 브랜치 `master` → 원격 브랜치 `main`)
- `calDateKey(y, m, d)`는 0-based month 사용 (내부에서 m+1 처리)
- 커밋 시 `.github/`, `관리앱/`은 무관한 별개 항목이므로 `git add -A` 대신 관련 파일만 명시적으로 스테이징할 것
